# 影子模式（Shadow Mode）

> 让强化学习策略先"当副驾驶"：跟线上规则一起跑，**只记录不生效**。
> 跑够一段时间、一致率达标，再考虑灰度。

---

## 1. 它解决什么问题

RL 策略是在仿真数据上训的。离线指标好 ≠ 线上好：

| 风险 | 说明 |
| --- | --- |
| 数据分布差异 | 真实雷达/ADS-B 的噪声、丢包、时钟漂移和仿真不一样 |
| 误配代价高 | 一次误配就把两架飞机并成一条，空管看到的态势是错的 |
| 无法回滚 | 直接切换后出问题，只能紧急回退，影响面已经产生 |

影子模式把风险降到**零**：策略的输出只写日志，不进任何业务流程。

```
              ┌────────────────────────────┐
   实时观测 → │  TrafficStore.ingest()     │
              └────────────────────────────┘
                     │                │
                     ▼                ▼
          ┌──────────────────┐  ┌──────────────────────┐
          │ DedupEngine 规则 │  │ ShadowMatcher 策略   │
          │ （生效，对外输出）│  │ （不生效，只写日志）  │
          └──────────────────┘  └──────────────────────┘
                                          │
                                          ▼
                                 logs/shadow.jsonl
```

---

## 2. 怎么开

```powershell
# 默认关闭，零影响；打开只需一个环境变量
$env:DEDUP_SHADOW = "1"
$env:DEDUP_SHADOW_LOG = "logs/shadow.jsonl"     # 可选
python -m uvicorn app.main:app --port 8080
```

**运行时开关**（演示台用，不必重启）：

```powershell
curl -X POST http://127.0.0.1:8080/api/traffic/shadow ^
     -H "Content-Type: application/json" ^
     -d "{\"enabled\": true, \"reset\": true}"
```

`reset: true` 会清零计数与环形缓冲，适合"每场演示重新开始"。

验证：

```powershell
curl http://127.0.0.1:8080/api/traffic/shadow
```

```json
{"enabled": true, "threshold": 0.3, "frames": 39, "edges": 2737,
 "observations": 390, "agree": 390, "policy_extra": 0, "policy_missed": 0,
 "agree_rate": 1.0}
```

`/api/traffic/stats` 的返回里也会带一个 `shadow` 字段。

## 3. 记录了什么

每处理完一帧，为每条观测写一行 `logs/shadow.jsonl`：

```json
{"ts": 1793253251.679, "frame": 5, "src": "A-RID", "lid": "A-1",
 "ua_id": "UA-0001", "rule_gid": "G-UA-0001", "policy_gid": "G-UA-0001",
 "p_max": 1.0, "agree": true}
```

| 字段 | 含义 |
| --- | --- |
| `rule_gid` | 线上规则把这条观测并给了哪条航迹（`null` = 新建） |
| `policy_gid` | 策略认为应该并给哪条航迹（`null` = 新建） |
| `p_max` | 策略对这条观测所有候选边的最高概率（看它有多"自信"） |
| `agree` | 两边判断是否一致 |

统计口径：

| 计数 | 含义 |
| --- | --- |
| `agree` | 判断相同 |
| `policy_extra` | 策略多并了（规则没合） |
| `policy_missed` | 策略少并了（规则合了） |
| `structural` | 规则匹配到**本帧新建**的航迹（策略快照里没有，不算它错） |

## 4. 出日报

```powershell
python tools/report_shadow.py                    # 默认读 logs/shadow.jsonl
python tools/report_shadow.py --samples 10       # 多打几条分歧样本
```

输出：

```
==================================================================
 影子模式报告  logs\shadow.jsonl
==================================================================
  帧数 39 ｜ 观测 390 ｜ 策略日均推理 390 次
------------------------------------------------------------------
  指标                             数量       占比
  一致（判断相同）                      390   100.0%
  策略多并（规则没合）                      0     0.0%
  策略少并（规则合了）                      0     0.0%
  两边都改判到别的航迹                      0     0.0%
------------------------------------------------------------------
  一致率 100.0%  →  ✅ 可以进入灰度
```

判定门槛：**≥95% 且误配为 0** 才进入灰度。

## 5. 实测结果（演示场景，40 帧 × 10 观测）

| 指标 | 数值 |
| --- | --- |
| 帧数 | 39 |
| 候选边 | 2737 |
| 观测 | 390 |
| 一致 | **390（100%）** |
| 策略多并 / 少并 | 0 / 0 |
| 单帧推理耗时 | 70 条边 ≈ 18 ms（261 µs/边，纯 Python） |

> 首次跑是 99.7%，那 1 条是模拟器**故意重复发一条报文**（演示幂等）造成的，
> 策略看到两条、规则按幂等键只算一次。已在影子里跳过同帧重复观测。

## 6. 工程细节（踩过的坑）

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| 依赖 numpy | 项目 `.venv` 没装 numpy | 改成**纯 Python 推理**，不给线上加依赖 |
| 权重方向 | Paddle 的 `Linear` 是 `[in, out]` | 加载时转置成 `[out][in]` |
| 概率饱和 | 很多边都是 `p=1.000`，排序随机 | 用 **logit 排序 + 距离二次排序** |
| 同帧新建航迹 | 快照里没有，策略必然"看不见" | 单独计 `structural`，不算它的错 |
| 重复报文 | 同帧重复发同一条 | 按 `(source, local_id)` 去重 |
| 首帧无候选 | 第 1 帧还没有航迹 | 自然跳过（不产生边） |

---

## 7. 局限

1. **影子模式不学习**：只验证，策略不会在影子期改进（在线学习要用 A/B 或 bandit）；
2. **没有真值**：一致率高只说明"和规则像"，不代表"更对"；
   要么人工抽检分歧样本，要么用**事后轨迹回看**做代理真值；
3. 当前演示场景规则本来就接近最优，所以一致率 100%；
   **真正有价值的是在密集/蜂群场景跑**，那里两者的分歧才会暴露出来。

---

## 8. 下一步

| 步骤 | 做法 | 通过条件 |
| --- | --- | --- |
| ① 影子（当前） | 只记录 | 一致率 ≥95%，误配 0 |
| ② 灰度 | 仅密集场景生效（`DEDUP_POLICY=on&scope=dense`） | 指标不劣于规则 |
| ③ 全量 | 完全切换，规则留作 fallback | — |

落地建议：**先拿真实回放数据跑影子**，分歧样本逐个人工看，再决定要不要灰度。
