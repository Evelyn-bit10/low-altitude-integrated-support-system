# 无人机停靠算法 Demo

基于 PySide6 的桌面仿真系统，演示多无人机进入等待区后触发停靠调度、停机位分配、入场/离场路径规划、偏航告警与飞手邮件通知。

## 最近更新

### v1.3.0 - 2026年更新
- **新增传感器数据面板**：底部面板集成三路 Modbus-RTU 传感器（风速风向 / 百叶箱温湿度气压光照 / 雨量），通过串口下拉选择 COM1~COM5，后台线程每 0.5 秒轮询并实时刷新数据
- **底部面板全宽布局**：ADS-B 雷达、天气、传感器三卡片横跨地图与侧栏全宽显示
- **默认地面站坐标**：GPS 定位失败时回退至重庆南岸区（29.52°N, 106.56°E），支持通过 `gcs.location_name_override` 覆写天气卡片位置名称
- **传感器串口下拉标准化**：风速/百叶箱/雨量三个串口选择改为纯下拉（COM1~COM5 + 系统检测端口），不可手动输入
- **传感器数据裁剪**：移除 PM2.5、PM10、CO₂、噪声、TSP 显示项，保留风速/风向/风力/温度/湿度/气压/光照/雨量 8 项核心数据

### v1.2.0 - 2025年更新
- **新增电池电量输入功能**：任务分配界面新增"电池电量(%)"输入框，支持指定无人机的初始电量（0-100%），默认值为50%
- **优化空域管制规则**：移除进场和出场的互斥限制，允许进场和出场同时进行，提高空域利用率和系统吞吐量
- **修复电量保持问题**：修复充满电的无人机在等待出场时电量下降的问题，现在 WAITING_OUTBOUND 状态下电量保持在100%
- **改进优先级调度**：修复无人机按优先级排序处理的逻辑，确保高优先级无人机优先获得机位分配
- **优化机位释放时机**：修改机位释放逻辑，无人机起飞时立即释放机位，避免已离开的无人机占用机位
- **增强分配原因显示**：优化机位分配原因的显示格式，按"优先级 → 停靠时长 → Best-Fit尺寸"顺序展示，增强可读性

## 功能概览

- **地图**：停机坪、等待区、机位、障碍物、禁飞区、监视范围；可选底图（`map.background_image`）；图层开关与高度标签；轨迹/路径渐隐。
- **路径**：网格 A* 避障 + Catmull-Rom 平滑 + 最小转弯半径约束（`path.min_turn_radius`）；进场高度收敛至地面，离场回升巡航高度。
- **调度**：任务机在加入场景时由 `DockScheduler` 预约机位（尺寸匹配 + 占用可行）；在候选机位中按综合分择优（距离、占用惩罚、充电倾向），详见下文「机位分配说明」。
- **仿真流**：接近 → 等待区排队 → 限流进场 → 停靠充电（可配置加速）→ 排队离场；进场/离场并发与间隔由配置约束。
- **告警**：偏航检测（距离阈值 + 持续时长）；系统告警邮件 `mock` / `smtp`（`config/demo_config.yaml` 中 `alert`），与飞手邮件相互独立。
- **飞手邮件**：机位分配成功、偏航持续超阈值后的告警，走 `gcs.pilot_smtp_*` 与 `PilotMailer`（见下文「飞手邮件（SMTP）」）。
- **地面站式界面**：侧栏含图层、机位管理、控制（演示与实况）、任务、无人机卡、通信与状态表；底部横跨全宽的 ADS-B 雷达 / 天气 / 传感器三卡片；默认地面站坐标重庆南岸区，可覆写位置名称。
- **传感器面板**：底部最右侧卡片，下拉选择串口（COM1~COM5），支持 Modbus-RTU 三路传感器实时采集（风速风向、百叶箱、雨量），后台线程每 0.5 秒刷新。
- **演示实况**：控制页「演示实况」随仿真刷新，展示机队状态、等待区人数、机位占用，以及**为何预约该机位**的多行说明（加入任务瞬间生成）。
- **启动机队**：首次启动按 `simulation.spawn_count` 在场景左侧生成随机仿真机；使用「演示」或连播「开始」会**清空场景**后只保留当次任务机。

## 演示操作（侧栏 → 控制）

- **开始**：启动主仿真时钟，并**按顺序自动演示**三个批次——多尺寸 → 多充电功率 → 混合。每一批在全部任务机**离场结束**后自动清空机位与仿真机，再进入下一批。
- **暂停**：停止主仿真时钟。
- **演示：多尺寸 / 多充电功率 / 混合**：先**清空**当前所有仿真任务机与机位预约，再只运行对应批次，并自动启动仿真（无需先点「开始」）。每批**第一架**成功入队的飞手邮箱会设为 `2076670913@qq.com`（与 `MainWindow` 中演示常量一致），若已开启飞手 SMTP 且配置完整，会在机位预约后尝试发送「机位分配」邮件。
- **偏航演示：脱离路径 / 恢复路径**：对**第一架**处于进场或离场、且已有规划路径的无人机切换演示状态（**不**再使用瞬移改坐标）：
  - **第 1 次点击**：进入「脱离路径」——侧向偏离规划折线，不沿航点推进；与规划线距离持续超过 `deviation.distance_threshold` 且达到 `deviation.duration_threshold_seconds` 后触发偏航告警，并可通过飞手邮件通知（消息中含 `deviation` 字样）；同时会为该机写入演示飞手邮箱（若尚未配置）。
  - **第 2 次点击**：进入「恢复」——飞向规划路径上最近点，进入约 3 m 容差后自动贴线并恢复沿航点飞行。
  - **第 3 次点击**（仍处于恢复阶段时）：立即贴合路径并恢复沿路径飞行。
- **任务**页可手动填写参数并「机位分配并生成路径」加入单机任务；分配成功后同样会尝试飞手机位邮件（若 SMTP 与飞手邮箱已配置）。无人机卡上「分配」对话框在手动选机位成功后也会发同一套通知。

## 机位分配说明（与代码一致）

任务机加入时，采用**9步分配算法**：

### 分配流程
1. **解析机型参数**：从配置中读取无人机的尺寸、充电功率需求、电池容量
2. **计算预计停靠时长**：根据电池容量、原始电量、充电功率计算需要的充电时间
3. **机型支持检查**：筛选出支持该机型的机位
4. **尺寸匹配检查**：筛选出尺寸足够容纳该无人机的机位
5. **功率匹配检查**：筛选出充电功率 ≥ 需求功率 × 50% 的机位
6. **空闲状态检查**：筛选出当前空闲或即将空闲的机位
7. **优先级排序**：按无人机优先级降序排列（高优先级优先）
8. **停靠时长排序**：优先级相同时，按预计停靠时长升序排列（快充快走）
9. **Best-Fit尺寸排序**：停靠时长相同时，按机位尺寸升序排列（避免资源浪费）

### 六大演示场景
- **场景一：相同优先级-按停靠时长**：A1(75%)、A2(30%)、A3(90%) → 按电量高低决定停靠时长，电量高的优先
- **场景二：不同优先级-高优先级优先**：B1(优先级0)、B2(优先级5)、B3(优先级10) → 完全按优先级决定
- **场景三：Best-Fit尺寸匹配**：C1(0.8m)、C2(1.8m)、C3(3.2m) → 小型机分配到小机位，避免浪费
- **场景四：功率不足-筛选失败**：D1(8.0kW)、D2(25.0kW)、D3(3.0kW) → 超高功率需求可能无机位满足
- **场景五：混合场景-综合测试**：E1-E4 → 综合考虑优先级、尺寸、功率、电量
- **场景六：电量差异-停靠时长对比**：F1(95%)、F2(50%)、F3(20%) → 优先级相同，按停靠时长排序

侧栏会生成详细的分配原因说明，包括机型匹配、功率匹配、充电预估、优先级、分配策略等信息。实现见 `src/engine/dock_scheduler.py`。

## 飞手邮件（SMTP）

配置在 `config/demo_config.yaml` 的 **`gcs`** 段（与独立子目录 `drone_ground_station` 无关）：

- `pilot_smtp_enabled`：是否启用飞手通知邮件。
- `pilot_smtp_host` / `pilot_smtp_port` / `pilot_smtp_username` / `pilot_smtp_use_ssl` / `pilot_smtp_use_starttls` / `pilot_mail_sender`：与 QQ 邮箱等 SMTP 服务一致即可。
- **授权码不要写入仓库**：`pilot_smtp_password` 在 YAML 中可留空，通过环境变量 **`PILOT_SMTP_PASSWORD`**（或 **`SMTP_PASSWORD`**）注入；亦可用 **`PILOT_SMTP_*`** 逐项覆盖 YAML。

启用后：机位分配成功、偏航告警记录进入告警列表后，会向该机在无人机卡中维护的**飞手邮箱**发 HTML 邮件（演示批次首架机会自动填入上述演示邮箱）。

## 系统告警邮件（`alert`）

编辑 `config/demo_config.yaml`：

- `alert.mode: mock`：模拟发送。
- `alert.mode: smtp`：真实 SMTP（需填写正确参数）。

用于偏航等告警的「系统侧」投递逻辑，与飞手 `PilotMailer` 配置分离。

## 调度与仿真参数（节选）

- `simulation.spawn_count`：启动时随机仿真机数量。
- `simulation.max_concurrent_inbound` / `inbound_dispatch_interval_seconds`：同时进场上限与放行间隔。
- `simulation.max_concurrent_outbound` / `outbound_dispatch_interval_seconds`：同时离场上限与间隔。
- `simulation.route_fade_per_second`、`trail_max_points`：路径与轨迹渐隐。
- `simulation.charging_acceleration`：停靠充电相对真实时间的加速倍数。
- `deviation.distance_threshold` / `duration_threshold_seconds` / `cooldown_seconds`：偏航判定与告警冷却。

完整字段见 `config/demo_config.yaml`。
