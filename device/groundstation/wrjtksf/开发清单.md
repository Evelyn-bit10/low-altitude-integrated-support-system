# 无人机停靠算法 Demo — 可执行开发清单

目标：把当前 PySide6 仿真 Demo 从“可演示”推进到“可验证、可复现、可交付”。

使用方式：按优先级从上到下完成；每项完成后在 `[ ]` 改成 `[x]`。

---

## 里程碑 A：Demo 先做完整、好用（P0）

### A1. README 与文件结构文档补齐（P0）
- [ ] **梳理 `src/` 结构与职责**
  - **产出**：`README.md` 增补 “目录结构/模块职责” 小节
  - **内容要求**：至少说明这些模块在哪里、负责什么、对外暴露什么入口
    - 仿真主入口（启动/暂停/注入偏航）
    - 调度/机位分配
    - 路径规划（A* / 平滑 / 最小转弯半径约束）
    - 地图要素（机位/障碍/禁飞区/底图）
    - 告警（偏航检测、邮件 mock/smtp）
  - **验收**：新同学按 README 运行成功，并能定位“机位分配入口在哪里”

- [ ] **补齐配置项说明**
  - **输入**：`config/demo_config.yaml`（若存在）
  - **产出**：README 增补 “配置项说明” 小节（列出关键参数的含义、范围、默认值含义）
  - **验收**：能看文档改出“同时允许进场 2 架”“路径渐隐更快”等效果

- [ ] **补齐演示脚本**
  - **产出**：README 增补 “演示脚本（按步骤点哪里）”
  - **验收**：从启动到“多机进场→分配机位→注入偏航→告警触发”全流程可复现

---

### A2. 侧边栏变窄、可拖拽、可折叠（P0）
- [ ] **侧边栏宽度约束与默认值优化**
  - **产出**：侧边栏默认宽度更窄（例如 240~320），且设置 min/max（例如 200~420）
  - **验收**：窗口 1366×768 下地图不被挤压得难看

- [ ] **支持拖拽调整宽度（Splitter）**
  - **产出**：左侧面板与地图之间可拖拽调整
  - **验收**：拖动顺滑，不会导致地图控件重绘闪烁/卡顿明显

- [ ] **支持一键折叠/展开**
  - **产出**：折叠按钮（或快捷键），折叠后地图获得最大空间
  - **验收**：折叠/展开不影响仿真运行；状态保留（再次展开控件内容不丢）

- [ ] **记住上次宽度（可选 P1）**
  - **产出**：本地持久化（例如 `QSettings`）保存 splitter 位置
  - **验收**：重启程序后宽度恢复

### A3. 机位分配（输入→校验→分配→失败原因）（P0）
> 目标：把 README 写的“机位分配输入输出”真正落成稳定功能，并可测试。

- [ ] **定义机位分配输入模型**
  - **输入字段**：
    - UAV ID（字符串/整数都行，但需唯一）
    - 机型（字符串）
    - 尺寸（长/宽/高度 或 半径/占位等级，二选一但要统一）
    - 所需充电功率（W/kW，单位统一）
    - 预计停靠时长（分钟）
    - 优先级（整数，越大越优先 或 越小越优先，必须写清楚）
  - **产出**：`AllocationRequest`（dataclass / pydantic 可选）+ 校验函数
  - **验收**：非法输入会给出明确错误（字段、原因）

- [ ] **定义机位资源模型**
  - **机位属性建议**：
    - 机位 ID
    - 可容纳尺寸上限
    - 最大供电功率
    - 当前占用状态（空闲/占用/预留）
  - **验收**：机位配置可从配置/常量中读取，便于扩展到 N 个机位

- [ ] **实现分配策略 v1（可解释、可复现）**
  - **建议策略（从强约束到软排序）**：
    - 强约束过滤：尺寸不满足 / 功率不满足 / 已占用
    - 排序：优先级高的先分；同优先级按“预计时长短优先”或“先来先服务”（二选一）
    - 机位选择：可用机位中选“最小满足”（best-fit）以减少资源浪费
  - **输出**：
    - 成功：机位 ID
    - 失败：原因枚举（无可用机位/尺寸不匹配/功率不足/参数非法/系统繁忙等）
  - **验收**：同一批输入多次运行，分配结果一致（除非你刻意引入随机）

- [ ] **UI 接入**
  - **产出**：输入表单 + 提交按钮 + 结果展示（成功/失败原因）
  - **验收**：用户能手动输入一架 UAV 并看到机位分配结果

- [ ] **测试用例（pytest）（P0）**
  - **用例建议**：
    - 尺寸不满足 → 失败原因正确
    - 功率不满足 → 失败原因正确
    - 4 个机位都占用 → 失败原因正确
    - 多架不同优先级 → 分配顺序正确
  - **验收**：`pytest -q` 通过，且能覆盖核心分支

## 里程碑 B：安全/告警“可验证”（P0→P1）

### B1. 横向偏差计算（实时位置 vs 理论轨迹）（P0）
- [ ] **明确偏差口径（写入文档/配置）**
  - **推荐**：对“规划路径折线（或平滑曲线采样点）”求最近点距离（2D 横向偏差）
  - **输出指标**：
    - 当前偏差（m）
    - 最近路径点/线段索引（便于调试）
  - **验收**：偏差随 UAV 接近路径而减小，离开路径而增大，数值连续不跳变

- [ ] **实现距离计算（线段投影）**
  - **产出**：`distance_point_to_polyline(p, path_points)` 工具函数
  - **验收**：对简单几何路径（直线/折线）手算对比一致

- [ ] **阈值与告警防抖（P1）**
  - **配置**：偏差阈值（m）、持续时间（s）、恢复阈值（迟滞）
  - **验收**：偏差在阈值附近抖动不会疯狂触发/恢复

---

### B2. 禁飞区/高度约束检查（P0）
- [ ] **统一禁飞区数据结构**
  - **建议字段**：
    - polygon（2D 多边形）
    - min_alt / max_alt（可为 None 表示不限制）
    - name / id
  - **验收**：能在地图上展示并能被算法读取同一份数据

- [ ] **点在多边形内判定**
  - **产出**：`is_point_in_polygon(point, polygon)`（射线法/绕数法）
  - **验收**：边界点策略明确（算在内还是算在外，需统一）

- [ ] **联动检查：进入禁飞区 或 超高度**
  - **产出**：实时状态 `OK / WARNING / VIOLATION`（可简化为是否触发）
  - **验收**：进入禁飞区立刻触发；离开后按策略恢复

---

### B3. 告警联动（P1）
- [ ] **告警事件结构化**
  - **产出**：`AlertEvent`（时间、UAV ID、类型、等级、关键数据、原因文本）
  - **验收**：UI/日志/邮件共享同一份结构化事件

- [ ] **邮件内容包含“证据数据”**
  - **包含**：偏差数值、触发阈值、禁飞区名称/高度范围等
  - **验收**：收到邮件就能定位问题，不需要再看界面

---

## 里程碑 C：多机冲突与路径质量（P1）

### C1. 冲突检测（P1）
- [ ] **路径-路径时空冲突判定 v1**
  - **建议**：对时间采样点进行最近距离检查（2D/3D），小于安全距离则冲突
  - **验收**：能检测到“同通道对向/追尾靠太近”的典型场景

- [ ] **冲突解决 v1：延迟放行**
  - **产出**：当冲突将发生时，后发 UAV 延迟进入通道/起飞
  - **验收**：冲突被消除，且 UI 中能看到“等待/放行”状态变化

---

### C2. 代价模型与更保守的 A*（P1）
- [ ] **加权代价**
  - **代价项建议**：靠近禁飞区边界/障碍物、急转弯惩罚、低高度惩罚
  - **验收**：相同起终点下，路径更远离危险区域（可视化可见）

---

### C3. 运动学约束前置（P1→P2）
- [ ] **在平滑/采样阶段保证最小转弯半径**
  - **验收**：不会出现“平滑后再裁剪导致撞障碍/入禁飞区”的反例

## 建议的执行顺序（强烈推荐）
- **先做**：A1 → A2 → A3（确保“能用且可说明”）
- **再做**：B1 → B2 → B3（把“安全与告警”做成可验证）
- **最后做**：D1（快速增强观感与复现）→ C1/C2/C3（提升多机真实度）→ D2/E3（交付质量）
