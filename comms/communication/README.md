# 低空起降点—飞行器实时通讯与态势系统（网页 Demo）

> 纯前端演示，位于 `communication/` 文件夹。模拟“起降点 ↔ 飞行器”之间的 C2 指挥控制、RID 远程识别、实时气象与障碍物情报融合通讯。

## 运行方式

直接用浏览器打开 `communication/index.html` 即可（单机演示模式，无需后端与网络）；也可与隔壁 `flycontrol` 项目联动（见下）。

```
communication/
├── index.html   页面结构（已引入 ../../shared/interface.js 统一接口适配层）
├── style.css    深色航空仪表风格样式
├── app.js       模拟引擎（RID / C2 报文 / 气象 / 障碍物 / 态势图 / 决策 + 双向同步）
├── decision_engine_demo.py  Python 核心决策引擎原型（通信 + 起降许可决策）
└── README.md    本说明
```

## 与 flycontrol 联动（统一接口，双向同步）

`communication`（通讯与态势）与 `flycontrol`（飞行程序规划）已通过 `../../shared/` 下的统一接口契约打通：

| 数据 | 方向 | 接口 |
| --- | --- | --- |
| 起降点 / 障碍物 / 空域 / 气象 / 飞行程序 | flycontrol → communication | `GET /api/sync/snapshot` |
| 实时飞行器态势（RID/C2） | communication → flycontrol | `POST /api/traffic/ingest` |

**使用步骤：**

1. 先启动后端：执行 `..\..\低空系统.bat api`（或双击工程根目录的 `低空系统.bat` 选 `[4] Backend only`），默认 `http://127.0.0.1:8080`，无 Postgres 自动回退 SQLite。
2. 再打开本目录 `index.html`（或执行 `..\..\低空系统.bat comms`）。
3. communication 顶栏会显示「已连接 flycontrol」，此时：
   - 起降点、障碍物、空域（限飞区）、气象、进近/离场飞行程序全部以 flycontrol 为准，并叠加显示在态势图上；
   - 每 ~1s 把本系统的飞行器态势回传 flycontrol（`GET /api/traffic` 可查）。

未启动 flycontrol 后端时，communication 保持「本地演示」模式，使用内置模拟数据，功能不受影响。

- 统一契约与字段映射：见 `../../shared/contract.md`、`../../shared/schema.json`；
- 适配层实现：`../../shared/interface.js`（JS）/ `../../shared/interface.py`（Python）；
- 坐标统一为 WGS84 经纬度 + 海拔 MSL，各项目内部仍用本地 ENU 平面（换算公式两边一致）。

## 设计依据（思路参考，不替代官方标准）

1. **《无人驾驶航空器飞行管理暂行条例》**（2024-01-01 施行）
   - 实名登记、唯一产品识别码 → Demo 中每架飞行器携带 `regNo` 与 `uaId`；
   - 隔离飞行、飞行活动申请 → Demo 中以“申请-批复”报文体现。
2. **CCAR-92 部《民用无人驾驶航空器运行安全管理规则》**
   - 运行分类与 C2 链路余度 → Demo 实时监测链路时延/丢包/RSSI，并给出“≤500 ms”符合性判定；
   - 远程识别（RID）要求 → Demo 按 1 s 周期接收 RID 广播，超过 3 个周期未收到即告警。
3. **《民用无人驾驶航空器空中交通管理信息服务系统数据接口规范》（MH/T 系列）思路**
   - 消息统一采用“消息头 + 载荷”的 JSON 结构：
     ```json
     {
       "protocol": "CAAC-UTM-C2/1.0",
       "messageHeader": {
         "messageType": "ATC_CLEARANCE_LAND",
         "messageId": "MSG-...",
         "sender": "ZBTJ-VP-01",
         "receiver": "UAS-2024-0001",
         "timestamp": "..."
       },
       "payload": { ... }
     }
     ```
4. **RID 广播字段**参考 ASTM F3411 思路：Basic ID / 位置 / 高度 / 速度矢量 / 航向 / 操作者位置 / 时间戳 / 紧急状态。
5. **起降点周边障碍物**：以障碍物位置、高度、半径构建简易障碍物限制面，飞行器进入“水平距离 < 障碍物半径 + 余量 且 高度 < 障碍物高度 + 余量”即触发冲突告警并自动下发避让指令。
6. **实时气象（MET）**：风向风速、阵风、能见度、云底高、温度露点、气压。低于演示阈值（能见度 < 1600 m、云底高 < 120 m、风速 > 8.0 m/s）时告警并自动向所有飞行器广播气象告警。

## 通讯报文类型

| 方向 | 报文 | 说明 |
| --- | --- | --- |
| 飞行器 → 起降点 | `RID_BROADCAST` | 每 1 s 广播身份、位置、速度、高度、紧急状态 |
| 飞行器 → 起降点 | `HEARTBEAT` | C2 链路心跳（3 s 周期） |
| 飞行器 → 起降点 | `POSITION_REPORT` | 位置报告（2 s 周期） |
| 飞行器 → 起降点 | `TAKEOFF_REQUEST` / `LANDING_REQUEST` | 起飞 / 降落申请 |
| 飞行器 → 起降点 | `C2_ACK` | 对起降点指令的应答 |
| 起降点 → 飞行器 | `ATC_CLEARANCE_TAKEOFF` / `ATC_CLEARANCE_LAND` | 起飞 / 降落许可 |
| 起降点 → 飞行器 | `HOLD_INSTRUCTION` / `GO_AROUND` | 等待 / 复飞指令 |
| 起降点 → 飞行器 | `WEATHER_BROADCAST` / `OBSTACLE_ALERT` | 气象广播 / 障碍物冲突告警 |
| 起降点 → 飞行器 | `LINK_CHECK` / `C2_FREE_TEXT` | 链路检查 / 自由报文 |

## 演示脚本（自动运行）

- 05 s：`UAS-2024-0003` 申请起飞 → 起降点许可；
- 10 s：`UAS-2024-0001` 申请降落 → 起降点许可，随后进近着陆；
- 22 s：`UAS-2024-0005` 申请起飞 → 空域占用，起降点下发等待指令，32 s 再许可；
- 42~78 s：能见度降至标准以下 → 气象告警、广播气象告警，`UAS-2024-0004` 进近时收到复飞指令，天气好转后重新申请降落；
- 58 s：注入 `UAS-2024-0002` RID 丢失 4 秒告警（RID 失效期间自动决策 DENY）；
- 全程：障碍物冲突检测、RID 丢失模拟、链路质量监测。

## 豆包回答参考价值评估（简评）

有价值的点（已吸收到本 Demo / 原型）：
- 分层架构：数据源接入 → 业务计算 → 通信服务 → 终端 → 存储审计，工程落地思路清晰；
- 消息分四类：通告、飞行器申请、决策指令、心跳保活——本 Demo 消息流已覆盖；
- 决策引擎输出 `APPROVE / DENY / ADVISE_HOLD / WARNING` 并附原因，指令带 `validUntil` 有效期（本 Demo 已加入，60 s 超时需重申请）；
- 断线降级策略：链路丢失、RID 失效、气象源失效时限制自动许可——本 Demo 左侧符合性表与 `autoDecision()` 已体现；
- 链路选型：5G/4G 主链路 + 数传备份 + 卫星兜底，符合 CCAR-92 部 C2 链路余度思路。

有误 / 缺漏的点（本实现已修正或注明）：
- 时间戳示例误用全角 `‑` 连字符，Python `strftime` 会原样输出导致非标准 ISO8601——`decision_engine_demo.py` 已改为 ASCII `-`；
- Python 伪代码中障碍物净空评估为空实现、`WARNING` 分支缺失——`decision_engine_demo.py` 已补上简化净空计算与 WARNING 分支；
- 决策代码未校验 RID 合法性与实名登记——原型已补上；
- 示例阈值（风 12 m/s、能见度 2000 m、云底高 300 m）为通用示例，实际需按机型/运行类别/局方审定配置，不可直接照搬；
- 未提中国特色的北斗短报文备份链路，未提 MH/T 系列 UTM/USSP 数据接口具体对接，实际工程需补充。

## 说明

- 豆包链接为思路参考，本 Demo 未按该回答逐条执行；所有数据（坐标、气象、障碍物、飞行器）均为模拟值，用于演示软件通讯流程与界面，不构成实际运行依据。
